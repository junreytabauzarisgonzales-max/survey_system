# Student Survey Creator API, schema and integrity contract

## Authentication and authorization

`POST /api/register` accepts `{name,email,password}` (minimum 8 characters) and returns the same session payload as login. Self-registration is open, rate-limited per client address and creates a non-administrator workspace owner. `POST /api/login` accepts `{email,password}` and returns `{token,expires_at,user}`. Supply `Authorization: Bearer <token>` on authenticated requests. Sessions expire after 12 hours. Passwords are PBKDF2-SHA256 hashes with individual random salts (600,000 iterations). Tokens are random and only their hashes are stored. Login attempts are rate-limited per client address in the running server process.

Web tokens are stored in session storage. Android tokens are stored through `flutter_secure_storage`. `POST /api/logout` revokes the current token. Project authorization is rechecked per request, export, correction and synchronization event.

Any authenticated user can create surveys, duplicate surveys they manage and apply starter templates. The global administrator can additionally create accounts, list all users and access every project. Project roles:

| Role | Read | Collect / correct own | Manage structure / team | Read other researchers |
|---|---|---|---|---|
| researcher | yes | yes | no | no |
| viewer | yes | no | no | yes |
| manager (workspace owner) | yes | yes, including others | yes | yes |

Identifiable-data access is an additional project permission. It controls respondent profiles, protected answers, coordinate/media values and protected exports. By default exports exclude these even for administrators. Archived projects remain readable/exportable; new collection and corrections are disabled.

## Endpoints

All bodies are JSON objects. API errors are `{error: "message"}` with an appropriate HTTP status. UUIDs are generated by clients for offline interviews/events or by the server for configuration resources.

| Method | Path | Function |
|---|---|---|
| GET | `/api/health` | Health check |
| POST | `/api/register`, `/api/login`, `/api/logout` | Register, sign in/out |
| GET | `/api/me` | Current user |
| GET, POST | `/api/users` | List/create accounts (administrator only) |
| GET | `/api/templates` | Editable starter definitions |
| POST | `/api/templates/{id}/apply` | Copy a starter into the caller's account as draft resources |
| GET, POST | `/api/projects` | List authorized/create surveys (any authenticated user) |
| PUT | `/api/projects/{id}` | Update project with expected revision |
| DELETE | `/api/projects/{id}` | Permanently delete the survey and all of its data; requires manage access and `{confirm_name}` matching the current title |
| POST | `/api/projects/{id}/duplicate` | Copy configuration/forms as drafts, excluding respondents/interviews/team; requires manage access |
| GET, PUT | `/api/projects/{id}/members` | Read/upsert team assignment by `user_id` or exact account `email` |
| GET, POST | `/api/projects/{id}/forms` | List/create questionnaire drafts |
| GET, POST | `/api/projects/{id}/public-links` | List/create public survey links (manager) |
| PUT | `/api/projects/{id}/public-links/{linkId}` | Change name, expiration or enabled state with expected revision |
| GET | `/api/public/surveys/{token}` | Read the shared version only; no account required |

| PUT | `/api/projects/{id}/forms/{formId}` | Update draft with expected revision |
| POST | `/api/forms/{id}/publish` | Publish immutable version from `{revision}` |
| GET | `/api/projects/{id}/versions` | Published schemas with original names/labels/consent |
| GET, POST | `/api/projects/{id}/respondents` | Read/create protected profiles with schema snapshot |
| GET | `/api/projects/{id}/interviews?limit=200&after={uuid}` | Keyset-paginated interviews; maximum page size 500 |
| GET | `/api/interviews/{id}` | Authorized original interview and correction history |

| POST | `/api/interviews/{id}/attachments` | Upload authorized immutable media resource |

| POST | `/api/projects/{id}/retention` | Apply configured retention with `{confirm_project_id}` |

History kinds: `project`, `form`, `version`, `membership`, `respondent`, `public_link`. All are project-scoped and require manager access; respondent history additionally requires identifiable-data access.

Deleting a survey requires the exact current title in `confirm_name`. It transactionally removes questionnaires, published versions, public links and receipts, responses, corrections, attachments, respondents, team assignments, export/retention audits, sync results and project history. The survey and its public links then return 404. Published versions remain protected from ordinary deletion by a database trigger; an internal deletion marker permits the purge only inside this confirmed operation. Files already downloaded and older database backups are not erased.

## Public survey links and submissions

Create with `{name,version_id,expires_at?}`. Only a manager of that version's project can create links. If the version contains protected questions, coordinates or media, identifiable-data access is required as well. The response includes a random 256-bit URL-safe token; the web app constructs `/survey/{token}` using its current origin. Listing tokens requires manager authorization. Never derive sharing addresses from an untrusted request host header.

Update with `{name,enabled,expires_at,revision}`. `expires_at` is a timezone-aware ISO 8601 timestamp or `null`; new links must expire in the future. Version, project, creator and token cannot be changed. Create a new link to share a new version. Both changes and creation have project-scoped history.

Anonymous `GET` returns only `{title,project_name,version_number,schema,locations}`. The version's original form name, consent, question definitions/labels and the link's location snapshot are used. Disabled/expired/archived links or links whose creator no longer has the required active grants return 410. Unknown tokens return 404. No anonymous route lists or reads submissions, private project configuration or protected file downloads.

Submission body:

```json
{
  "submission_id": "21b1750b-6a91-4136-a30f-1ed3b506c7ec",
  "consent": true,
  "location_consent": false,
  "location": null,
  "answers": {"QUESTION-UUID": {"state":"answered","value":"A respondent's answer"}},
  "attachments": []
}
```

The same declarative, typed validation and required/conditional/missing-state rules apply. The server supplies the questionnaire version, project, collection timestamp and interview UUID; attempts to supply staff IDs, other version IDs or unknown top-level fields are rejected. Public interviews are completed immediately, have `source=public_link` and `researcher_id=null`, and use the existing immutable-original/correction/export model. Staff corrections still require normal project authorization. Researcher own-row scoping excludes public responses rather than attributing them to the link creator.

The response is only `{submitted:true,receipt:<UUID>}`. The client keeps its submission UUID and exact payload during uncertain failures. The submission UUID and canonical fingerprint prevent a retry from creating a second interview; reusing a key for different answers/link is a 409 conflict. Existing identical receipts can be acknowledged after link closure or retention without reopening collection or recreating deleted interviews. Intentional separate responses use new UUIDs; there is no identity-based one-person limit.

Media answers reference UUIDs supplied in the same submission's `attachments:[{id,question_id,filename,mime,content}]`, where content is base64. Every media reference must have a matching file for the same question, IDs cannot reference another interview's attachment, and total decoded attachment content is limited to 10 MiB. Files and completed answers are committed together. Public links cannot read uploaded files afterward.

Public API requests omit authenticated bearer credentials. The server currently permits up to 60 public POST requests and 180 other public requests per observed client IP per minute. Behind a reverse proxy the observed address may be shared; forwarded IP headers are not implicitly trusted. Public pages require network access for submission and do not persist answers in browser storage.

## Project configuration

Project create/update:

```json
{
  "name": "Community wellbeing",
  "description": "An independent study",
  "revision": 1,
  "archived": false,
  "config": {
    "objectives": "Describe community needs",
    "consent": "Your approved voluntary consent statement",
    "locations": [{"id":"north","label":"North district"}],
    "categories": [{"id":"resident","label":"Resident"}],
    "retention_days": 3650
  }
}
```

`config.fields` optionally contains a questionnaire schema for protected respondent profiles. A profile stores its field definitions together with its data, so future configuration changes do not reinterpret it. Locations/categories use stable configurable identifiers; they are never database table names or source-code enums.

## Questionnaire schema engine v1

Create a form with `{name,draft:<schema>}`. Update using the same shape plus the current `revision`. Publication snapshots the draft, form name and current consent statement and assigns a version UUID and increasing version number.

```json
{
  "engine_version": 1,
  "sections": [{
    "id": "ad1791c1-3e16-49b1-8624-a22dd26a9462",
    "label": "Participation",
    "questions": [
      {
        "id": "7768f5e8-1867-49d5-a884-d80e7acc6ee1",
        "label": "Would you like to describe your experience?",
        "type": "boolean",
        "required": true,
        "sensitive": false
      },
      {
        "id": "ff163bae-9799-44f0-8ed7-4fbbca5df53d",
        "label": "Describe your experience",
        "type": "text",
        "description": "Use your own words",
        "help": "Do not enter names here",
        "validation": {"max_length": 2000},
        "condition": {
          "question_id": "7768f5e8-1867-49d5-a884-d80e7acc6ee1",
          "op": "equals",
          "value": true
        }
      }
    ]
  }]
}
```

Supported types: `text`, `single`, `multiple`, `number`, `currency`, `date`, `time`, `rating` (bounded numeric scale), `boolean`, `media`, `location`.

- `single`/`multiple` require `choices:[{code,label}]`. Codes are stable ASCII `[A-Za-z0-9_-]` identifiers, maximum 80 characters. Change labels freely in later versions; do not repurpose the meaning of a code or UUID.
- Numeric validation: `min`, `max`; text: `min_length`, `max_length`; multiple choice: `min_selections`, `max_selections`. Bounds must be finite and ordered. Unrecognized validation operators are rejected. Author-supplied regular expressions/scripts are not supported.
- Optional `default` is a typed answer value validated against the question. Defaults are applied by renderers only where visible.
- `condition` supports `equals`, `not_equals`, `contains` and `answered`, referencing an earlier question. `contains` requires a multiple-choice code. Earlier-only references prevent cycles and make evaluation deterministic. Hidden answers are normalized to `skipped`, not negative or zero responses.
- Sensitive questions, coordinates and media are protected. Stable UUID/type identity is checked against prior publications; an incompatible type change requires a new question UUID (duplicate the question and remove the old draft question).
- Published schemas are protected by database triggers against updates/deletes. Future engines must increment engine compatibility and add explicit render support; unsupported engine versions cannot replace the working offline cache.

## Answer and synchronization event

```json
{
  "event_id": "af6fb90b-881d-4daf-bdab-a30e909b1958",
  "id": "df0f9adb-d811-488a-84e2-d2b1c61b4221",
  "version_id": "e7b4ea8d-78db-4075-86b1-715087fe915d",
  "status": "completed",
  "consent": true,
  "location_consent": false,
  "location": "north",
  "created_at": "2026-10-25T10:00:00.000Z",
  "answers": {
    "7768f5e8-1867-49d5-a884-d80e7acc6ee1": {"state":"answered","value":false}
  }
}
```

Answers use explicit states: `answered`, `missing`, `skipped`, `not_sure`, `prefer_not_to_answer`. Only `answered` carries `value`. Missing keys are normalized to `missing` or `skipped` using the original version. Completion requires consent and nonempty visible required fields. Explicit uncertainty/refusal satisfies requiredness without fabricating an answer. Drafts can contain incomplete required fields.

Values: choice code/string; multiple-code array; numeric JSON number without currency symbols; boolean; ISO calendar date/time; `{latitude,longitude}` with explicit consent; media UUID-reference array. Coordinate/media questions also require protected-data permission.

Creation binds the researcher to the authenticated user. Updating a draft requires its current `revision`; version IDs cannot change. Completion freezes the original submission. The event UUID is globally unique and tied to the actor and canonical payload fingerprint. Repeating an identical authorized event returns the original result; changed payloads with the same key or fresh events attempting to replace completed interviews return conflict errors. Each accepted event and interview write commits in one transaction.

Corrections accept `{id?,answers,reason,base_correction_id}`. `id` is a client UUID for retry safety. Answers are a full corrected snapshot; the original row is untouched. The base ID must match the latest correction, including `null` for the first. Insertion sequence defines correction order even when timestamps match. Corrections are append-only, apart from explicit authorized retention.

Attachment uploads accept `{id,question_id,filename,mime,content}` with base64 content, maximum 10 MiB. The interview must exist first. Allowed MIME types: JPEG, PNG, MP4 audio, MPEG audio, WAV audio and PDF. Retrying an attachment ID must match the original metadata/content. Answer references and media uploads synchronize as separate resources; a reference can precede its upload when connectivity is interrupted.

## Export/analytics request

```json
{
  "project_id": "YOUR-PROJECT-UUID",
  "form_ids": [],
  "version_ids": [],
  "question_ids": [],
  "format": "analysis",
  "status": "completed",
  "from": "2026-01-01T00:00:00Z",
  "to": "2026-12-31T23:59:59.999Z",
  "location": "north",
  "researcher_id": "OPTIONAL-RESEARCHER-UUID",
  "include_identifiers": false,
  "original": false,
  "anonymize": false,
  "delimiter": ",",
  "metadata_fields": ["status","created_at","updated_at"],
  "answer_filters": [{"question_id":"QUESTION-UUID","op":"state","value":"not_sure"}]
}
```

Empty form/version/question selections mean all authorized fields in the project. Date bounds are inclusive, normalized to UTC, and apply to interview collection time, not correction time. Answer-filter operators are `equals`, `contains` (multiple choice), `gt`/`lt` (numeric), and `state`. Up to 20 filters are combined with AND. Filtering on excluded protected questions is rejected rather than leaking counts. The web UI provides one answer filter; the API supports multiple.

Mandatory metadata: project, interview, version, export timestamp and collection `source` (`researcher` or `public_link`). Optional metadata: status, location, collection/update timestamps and correction ID. The optional `source` request filter selects either collection source. `include_identifiers` adds protected questions and respondent/researcher UUIDs only after permission checks; public responses have an empty researcher field. `anonymize` cannot be combined with identifiers: it creates per-export interview pseudonyms and omits location, collection/update timestamps and correction IDs.

Analytics uses the same row/answer filters plus `group_by_location`. Each question/version/location accumulator reports total eligible interviews, answered count, counts by missing state, category counts/percentages, and numeric sum/min/max/mean/median/mode/stdev plus an eight-bin histogram where applicable. Percentages use answered interviews; unanswered/skipped values never become false/zero. Multiple-choice percentages may exceed 100% in total. Versions are kept explicit rather than assumed semantically compatible.
